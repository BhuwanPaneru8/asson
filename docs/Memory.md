## 1. What this is (30 seconds)

**Asson** is a Nepali clothing brand: *classic clothing, quality fabric, fair prices*. It starts menswear-first with 8 core products. **Asson Commerce OS** (this repo) is the one system the whole company runs on: online storefront, operations admin, payments, and (later) the store POS, procurement and accounting hooks. It delivers to all 77 districts of Nepal and is COD-first, with eSewa and Khalti.

Founder priorities, in order: **accuracy → accountability → fast checkout → automatic inventory → payment reconciliation → profit visibility → simple staff operation → owner control.**

## 2. Run it

```bash
npm install
cp .env.example .env     # DATABASE_URL, AUTH_SECRET; eSewa UAT keys for local payments
npm run db:migrate       # schema + search indexes
npm run db:seed          # ⚠ WIPES the DB. Demo data + accounts (credentials at the top of prisma/seed.ts)
npm run dev              # http://localhost:3000 · admin at /admin
npm run typecheck && npm run lint && npm test && npm run test:e2e   # must all pass before merging
```

The local DB is named `threadline` (pre-rename name; harmless). Demo staff and customer accounts use `@asson.test` emails.

## 5. Things that will bite you

1. **Next 16 is different.** Middleware is `src/proxy.ts`; `params` are Promises; `revalidateTag` needs two args; `refresh()` exists for server actions. Read `node_modules/next/dist/docs/` before using unfamiliar APIs.
2. **`cacheComponents` is OFF** on purpose. Use `unstable_cache` with tags `products` and `catalog`. Don't add `"use cache"`.
3. **Prisma drops indexes it doesn't know.** A migration once silently dropped the trigram search index. Read every generated `migration.sql`. The full-text index is an expression index in the `search_indexes` raw migration (function `product_search_doc`); the trigram index is declared in the schema.
4. **Money is integer paisa.** `formatPrice()` gives "Rs. 2,399". Discounts round down to whole rupees.
5. **Province is derived from district** (`withProvince`); never ask for both. The delivery fee comes from the **`DeliveryRate` row for the district** (`getDeliveryRates()` → `rateFor()` → `deliveryFee()`), never from hard-coded zones. After adding a Prisma model, **restart the dev server**: the cached Prisma client won't know the new table.
6. **Stock changes only via conditional update plus `InventoryLog`.** Order status only via `transitionOrder()` (state machine in `lib/order-status.ts`).
7. **Client components can't import server-only modules** (`lib/orders.ts`, `lib/catalog.ts`, …). Shared labels live in `lib/order-status.ts`, `lib/config.ts` and `lib/utils.ts`.
8. **React Compiler lint rules:** no `setState` in effect bodies, no components defined inside components, no `Date.now()` in render (use `now()`).
9. **eSewa docs' example signatures are wrong.** Our standard HMAC-SHA256 base64 over `total_amount=…,transaction_uuid=…,product_code=…` **is accepted by the UAT sandbox** (tested; tampered signatures are rejected with ES104). eSewa appends `?data=` to the success URL, so our return URLs carry the reference in the **path**.
10. **Khalti:** sandbox base `https://dev.khalti.com/api/v2`, header `Authorization: Key <secret>`, amount in paisa (min Rs. 10). Only lookup status `Completed` = paid; `Pending` and unknown statuses are held for review, never auto-cancelled. The sandbox key needs a merchant signup at test-admin.khalti.com.
11. Cookie names are still `tl_session` and `tl_cart` (legacy prefix). Renaming them logs everyone out; do it only before launch.
12. **POS sales are Orders** (`channel: STORE`, `paymentMethod: IN_STORE`, status DELIVERED) with `Tender` rows; they share stock and the order ledger with online orders. `createPosSale` is idempotent via `clientRef`. Demo PINs: owner 1357, manager 2580 (dev seed only).
13. **Money and stock rules for returns and purchasing:** refunds are per-unit `unitPrice × (subtotal − discount) / subtotal` (never more than was paid). Cancelling or returning an order through the admin restocks only units not already returned at the till. Goods receipts add only counted good units; cost = weighted average of on-hand stock and the landed unit cost. Purchase cost and profit are visible to the owner only (`finance` permission); never send `costPrice` to the till or the storefront.
14. **`prisma migrate dev` refuses to run non-interactively** when it wants confirmation (e.g. a new unique column). Generate SQL with `prisma migrate diff --from-schema-datasource … --to-schema-datamodel … --script` into a new migration folder, review it, then `prisma migrate deploy`.
15. **Testing:** `npm test` (unit + integration on `asson_test`, created with `createdb asson_test`) and `npm run test:e2e` (builds into `.next-e2e`, seeds `asson_e2e`, starts on :3100, clears `.next-e2e/cache` first). Integration tests mock `next/headers`, `next/cache`, `next/navigation`, `next/server` and `@/lib/auth` (`actAs(user)`). Prisma refuses `migrate reset` when run by an AI agent without the owner's explicit consent; use `migrate deploy` plus the seed instead.
16. **Next's data cache lives on disk** (`<distDir>/cache`) and survives restarts. If the database is replaced (re-seed), cached product pages keep old IDs. Clear the cache whenever the DB is swapped out. In a debugging session I mistook this for a Prisma connection stall, so check the database log (`log_statement`) before blaming drivers.
17. **Never disable the only submit button of a form that takes barcode input:** browsers ignore Enter then, dropping fast scans.
18. **The seed wipes everything; `prisma/bootstrap.ts` and `prisma/catalogue-starter.ts` never do** (they only add missing rows; starter stock is written to the inventory ledger). Production gets reference data (categories, delivery rates, suppliers from `prisma/reference-data.ts`, shared with the seed) via `deploy/with-db.sh production npx tsx prisma/bootstrap.ts`, which only adds missing rows. Never point the seed at a shared or production DB (it refuses when `NODE_ENV=production`).
19. **Loyalty bookkeeping lives in `lib/loyalty.ts`** and is called from `transitionOrder` (DELIVERED earns, CANCELLED refunds spent points, RETURNED takes back earned points), `processReturn` and `createPosSale`. Spending is a conditional decrement on `User.points` inside the order transaction; `PointsEntry` is the audit ledger. Points come off **after** the coupon, and the free-delivery threshold is judged **before** points. Refunds and P&L treat `Order.pointsDiscount` as a discount.
20. **Anything that adds stock must call `queueBackInStock(tx, variantIds)`** in the same transaction (receiving, adjustments, cancel/return restock, store returns), then dispatch with `after()`.
21. **A browser pane in the background delays React hydration** until the first interaction. Effects (recently viewed, checkout quote) look "broken" in that state; click or scroll first before concluding.
22. **Builds are per environment.** `NEXT_PUBLIC_SITE_URL`, `ASSON_ENV` (staging = noindex) and `ASSON_RELEASE` are baked in at build, so `deploy/build-bundle.sh <env> <url>` builds once per target. Standalone output is only on with `NEXT_OUTPUT=standalone` (tests use `next start`).
23. **Staging demo staff logins (`*@asson.test`, non-customer) are locked** with an unknown password (9 Nov 2026); the owner signs in with their own account. A re-seed recreates them with the passwords in `prisma/seed.ts`, so re-lock them afterwards (see deploy/README.md).
23a. **After re-seeding staging, clear its data cache** (`rm -rf /srv/asson/staging/current/.next-bundle/cache` then restart) — gotcha 16 applies on the server too.
24. **Production migrations are never rolled back** by `deploy/release.sh`; only the code switch is. Keep each migration backward compatible with the previous release.
25. **Rate limiting reads the visitor IP via `lib/client-ip.ts`** (CF-Connecting-IP first). Don't read `x-forwarded-for` directly: its first entry is client-controlled behind Cloudflare.
26. **Photos: never resize on the server** (1 GB box). Upload goes browser-resize → `POST /api/admin/media` → `lib/media.ts`. Stored files are immutable; a new photo is a new hash. `MEDIA_DIR` is required in production (startup check); new env files get it from `server-setup.sh`. Back up `/srv/asson/<env>/media` together with the database when moving servers.
27. **Spreadsheet import never changes stock of existing variants and never deletes anything.** Blank cells = unchanged. New variants' stock is logged as RECEIVED "Spreadsheet import". Generated SKUs continue `AS-#####` under a Postgres advisory lock (`pg_advisory_xact_lock(4417001)`), so any other code that generates AS- SKUs must take the same lock. Preview and import run the same planner; the import re-plans on the server.
28. **Every new staff action that changes data must call `audit(tx, staff, {...})` inside its transaction** (`lib/audit.ts`). Never put passwords, PINs, tokens or hashes in `changes`; cost fields are redacted for viewers without `finance`. `AuditLog` rejects UPDATE/DELETE (trigger), but TRUNCATE still works (tests use it) — never truncate it in production. Customer actions belong on the order timeline (`OrderEvent`), not the audit trail.
29. **Stock lives at locations.** Change it only with `moveStock` / `allocateOrder` / `restockOrder` / `zeroVariant` in `lib/stock.ts` (or `lib/transfers.ts`), inside the caller's transaction. Writing `Variant.stock` directly raises `Variant.stock is derived from StoreStock`; create variants with stock 0 and then add stock at a location. A `StoreStock` row can't be deleted while it holds units (deleting the variant cascades fine). Scripts that can't import `server-only` modules (seed, `catalogue-starter.ts`) write `StoreStock` + `InventoryLog` rows themselves. The migration put all existing stock at `FLAGSHIP` (a shop, priority 10); the owner should rename it or mark it a warehouse at `/admin/locations` if that's where the stock physically is.
30a. **Pickup orders reuse the order states with different meaning** (`PICKUP_TRANSITIONS`, `statusLabel(status, pickup)` in `lib/order-status.ts`): PACKED = ready at the shop, DELIVERED = collected; SHIPPED is not allowed. `transitionOrder` refuses DELIVERED for pickup orders unless `handover: true` (only `collectPickup` sets it), so payment always lands in a drawer. Cancelling a ready/collected pickup order restocks **at the pickup shop** (that's where the goods are), not at the allocation source.
30b. **Raw SQL and time zones:** the database session runs in `Asia/Kathmandu`, but Prisma stores `timestamp` columns as UTC wall time. In raw SQL never compare columns with `now()`; use `"col" AT TIME ZONE 'UTC'` against a bound `${date}::timestamptz` (see `claim()` in `lib/jobs.ts`; the bug made every failed job retry immediately until a test caught it).
30c. **Use `reportError(where, err)` (`lib/errors.ts`) instead of `console.error`** for anything a human should see; it still logs, never throws, and groups by fingerprint. Never put request bodies, headers, query strings or personal data in its `context`. New background work = a handler in `lib/job-handlers.ts` (idempotent!) + `enqueue(tx, type, payload, { key })` inside the business transaction.
30d. **Review migration SQL before applying it, never chain `migrate diff … && migrate deploy`.** `--from-schema-datasource` diffs against your local database; if it holds migrations from another (unmerged) branch, the diff tries to undo them (11 Nov 2026: a `DROP COLUMN "pan"` slipped into the funnel migration and ran locally; removed from the file and the column restored by hand). Grep every new migration for `DROP` before `migrate deploy`.
30e. **Any new action that changes stock, cash or a location's records must call `requireStoreAccess(user, storeId)`** (or go through a lib function that does) and catch `ScopeError` into a readable result. Tests: `makeUser(role)` gives staff all locations; pass `{ locations: [storeId] }` to test scoping. Browser cookies are shared across localhost ports: signing in on :3005 signs the owner's :3000 tab in or out too.
30f. **Storefront text goes through the dictionaries.** Add the English to `src/lib/i18n/en.ts` and the Nepali to `ne.ts` (typed against `en`: a missing key is a build error; a unit test checks the `{placeholders}` match). Server components: `const { t } = await getT()` (`lib/i18n/server.ts`); client: `const { t, l } = useT()`; sentences with links/bold: `rich(t("key"), { link: <Link/> })` (`lib/i18n/rich.tsx`). Shopper-facing server actions keep returning English and are wrapped in `localiseResult` (see the bottom of `actions/cart.ts`, `checkout.ts`, `track.ts`, `stock-alerts.ts`): `localise()` matches the English against the dictionary templates and fills in the values, so **a new shopper-facing message must be added to en.ts/ne.ts with the exact wording** or Nepali shoppers get English. Config text (`store.vatLabel`, `store.pickup.ready*`, express label/eta, zone labels) goes through `l()` the same way. Catalogue names: always render `pick(locale, x.name, x.nameNe)`; new product selects for the storefront must include `nameNe` (`cardSelect` does). SMS text lives in the dictionaries too (`sms.*`); keep English ones short (one 160-char segment). Keep digits 0–9 and "Rs."; Devanagari ignores letter-spacing (globals.css turns tracking off under `lang=ne`). Admin stays English.
30j. **Never write a new page with `cat >` / Write before checking the path is free** (`ls src/app/admin/<name>`). On 10 Nov 2026 the new My time page overwrote `/admin/me` (the Approval PIN page); caught before merge because git showed the file as modified, not added. Same trap as the `looks.ts` overwrite: check `git status` for `M` on files you think are new.
30i. **`prisma/seed.ts` wipes tables explicitly; every new table that references products, suppliers, stores or users must be added to its delete list (children first)**, or the second E2E run fails (`Foreign key constraint violated`). Supplier bills/payments were missing until 10 Nov 2026. Material quantities are milli-units everywhere in code (`toMilli`, `fmtQty`); only forms and pages show whole units.
30k. **Prisma `upsert` is not atomic** (it reads, then inserts): two concurrent first writes can both insert and one fails on the unique key. Where two people can create the same row at once, use `INSERT … ON CONFLICT DO NOTHING` (see `tick()` in `lib/ops.ts`), then lock and update.
30l. **Raw SQL that WRITES a time needs the same care as one that compares** (gotcha 30b): `SET "col" = ${date}` stores Nepal wall time (5 h 45 m off) because the session runs in `Asia/Kathmandu`. Write `SET "col" = (${date}::timestamptz AT TIME ZONE 'UTC')`, and compare the bare column against that, never `"col" AT TIME ZONE 'UTC'` against it (mixes timestamp and timestamptz). Found by the issues escalation test, 10 Nov 2026.
30m. **Search boxes that accept "a number or a phone" must not send a 10-digit phone to an `Int` column**: Postgres INT4 overflows and the page crashes (found by the care E2E, 10 Nov 2026). Only treat digits as a case/order number when they fit (≤ 9 digits); see `listCases()` in `lib/care.ts`. Also: after `prisma generate` for new models, **restart the dev server**, or it keeps the old client (`tx.careCase` is undefined).
30n. **E2E sign-ins reuse a session per account** (`signIn` in `tests/e2e/helpers.ts` keeps the `tl_session` cookie per worker). The login rate limit (8 per account per 15 min, same as production) locked the owner out once the suite had more than 8 owner sign-ins (10 Nov 2026). Don't raise the limit for tests; reuse the session.
30o. **Prisma `NOT` drops rows where the field is NULL** (SQL `NOT (x LIKE …)` is NULL, not true). To exclude some values of a nullable column, write `OR: [{ col: null }, { NOT: … }]` (found when expenses with no `source` never matched bank debits, 11 Nov 2026).
30h. **Never pass an unbounded list to `{ in: [...] }` or `Prisma.join`.** Postgres takes at most 32,767 bind values per statement; at national scale id lists exceed it and the query crashes. Use `inChunks()` (`lib/batch.ts`), or a relation filter / SQL join instead of fetching ids first. Don't `.find()` inside a loop over a big list (use a Map), and aggregate in SQL rather than loading every order into the app. Check new reports with `npm run bench:scale`.
30g. **`Sheet` renders into `<body>` (portal).** The sticky header's `backdrop-blur` makes it the box `fixed` children are measured from, so before 10 Nov 2026 the phone menu was squeezed into the 64px header bar. Don't put fixed overlays inside blurred/transformed parents without a portal.
30. **Tests:** `makeProduct({ stock, at })` puts stock at a location (default a `FLAGSHIP` shop); `makeLocation()` and `stockAt()` are in `tests/support/db.ts`.
